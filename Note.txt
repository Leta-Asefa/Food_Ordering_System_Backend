 Options ({ new: true, runValidators: true })
new: true: By default, findByIdAndUpdate returns the document before it was updated. Setting new: true ensures that the method returns the updated document after the update operation.
runValidators: true: This tells Mongoose to run schema validation before applying the update. If any of the new data doesn't pass validation (for example, a required field is missing or a field has an incorrect type), an error will be thrown.

How State Batching Works:
1. Synchronous Updates in Event Handlers
If you have multiple setState calls inside an event handler (or similar synchronous code), React groups those updates into one batch and schedules a single re-render:
E.g
function handleClick() {
  setCount(count + 1);
  setName('New Name');
}
Here, React will batch both updates and perform only one re-render.

2. Asynchronous Updates (Outside Event Handlers)
If setState is called inside asynchronous code, like in setTimeout,setInterval,Promise , React won’t batch those updates. Instead, it will schedule separate renders for each state update:
E.g
setTimeout(() => {
  setCount(count + 1); // Triggers a re-render
  setName('New Name'); // Triggers another re-render
}, 1000);
In this case, React will trigger two separate re-renders: one after setCount and another after setName.

Multiple Routes for Every Field
Pros:
Fine-Grained Control: Each route can be tailored to handle specific validation and logic related to a particular field, ensuring precise control over the data being updated.
Security: Limits the exposure of fields to be updated, potentially reducing the attack surface by only allowing updates on specific fields.
Clearer Intent: The purpose of each route is explicit, making it easier to understand what each route does.
Cons:
Increased Complexity: Managing many routes can become cumbersome, especially as the number of fields increases.
Code Duplication: Common logic for validation, authentication, and authorization may need to be duplicated across multiple routes.
Maintenance Overhead: More routes mean more places to update if the underlying data model changes.
Single Route for Updating Changed Fields Only
Pros:
Simplicity: A single route is easier to manage, reducing the complexity of the codebase.
Reduced Redundancy: Common logic can be centralized, avoiding duplication and making the code easier to maintain.
Efficiency: Only the fields that have changed are sent and processed, which can improve performance and reduce unnecessary data transfer.
Cons:
Validation Complexity: Validating different fields within the same route can be more complex, especially if different fields require different validation logic.
Security Risks: If not properly handled, it might expose more fields to updates than intended, potentially leading to security vulnerabilities.
Ambiguity: The route’s purpose may be less clear compared to field-specific routes, which can make it harder to understand what the route does without proper documentation.
